# Design review checklist

Use applicable questions and cite the changed screen, component, behavior, or test as evidence. Mark unrelated checks not applicable.

- Does the result follow the target project's documented design and existing UI patterns?
- Is the information hierarchy clear and are primary actions easy to identify?
- Are loading, empty, error, disabled, and success states handled where relevant?
- Does the change work with realistic and unusually long content?
- Does the layout remain usable at supported viewport sizes and zoom levels?
- Can the main interaction be completed with a keyboard, with visible focus?
- Are semantics, labels, contrast, status communication, and motion behavior appropriate?
- Are theme-specific behaviors covered if the project supports multiple themes?
- Were new components or styling mechanisms justified by project needs rather than plugin preference?
