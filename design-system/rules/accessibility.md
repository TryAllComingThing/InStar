# Accessibility

- Use semantic elements and accessible names that describe purpose.
- Ensure every interactive control is keyboard reachable and has a visible focus state.
- Preserve logical focus order; manage focus after dialogs, route changes, and dynamically inserted content when needed.
- Provide sufficient text and control contrast under the project's supported themes. Do not use color as the only status cue.
- Respect reduced-motion preferences and avoid unnecessary animation.
- Associate validation errors and help text with their fields, and announce important asynchronous status changes using established project patterns.
- Test key flows with keyboard-only interaction; use automated accessibility checks as supporting evidence, not as a replacement for manual review.
