---
name: initialize-project
description: Initialize a project for InStar, installing workflow guidance, conventions, planning directories and reviewer templates. Use when setting up or repairing the plugin integration.
compatibility: Requires the full InStar plugin package; controller and template assets resolve from the installed plugin root.
---

Resolve the target project’s existing absolute directory from the user’s task. Read the [controller protocol](../requirements-workflow/references/controller.md). Select the installation `stack` (`frontend`, `backend`, or `fullstack`); when omitted, use `fullstack` for compatibility. Invoke initialize with preview:true and inspect the result, then invoke initialize to apply the already-authorized setup. No extra confirmation is needed for requested initialization.

Do not overwrite local modifications. The initializer adds a marked AGENTS.md block and creates missing rules/reviewer templates. A valid unmodified InStar-managed block may be upgraded when the plugin guidance changes; a locally edited or ambiguous block is preserved and reported as a conflict. Re-running with a different `stack` reconciles the installation scope: it updates or removes only unchanged managed files and registrations no longer applicable, while preserving modified files and custom Codex settings. It always installs generic testing guidance and the generic reviewers architect, developer, code-reviewer, security-reviewer, and spec-reviewer. Frontend and fullstack installations additionally install frontend-conventions plus ui-reviewer and frontend-reviewer; backend installations do not install frontend-only assets. A fullstack installation registers seven roles under `.codex/config.toml`; a backend installation registers five. Architect, developer, ui-reviewer, code-reviewer, and security-reviewer have adjacent Markdown role contracts; spec-reviewer and frontend-reviewer define instructions in TOML. Merge missing registrations into valid TOML while preserving existing settings. Invalid TOML or same-name roles pointing elsewhere are reported without overwrite; report the final `agents.status`, registered, missing and removed roles. Codex loads project-level configuration only for trusted projects, so remind the user to trust the project if registered agents do not appear. Explain conflicts and reconcile only within the user’s authorized scope. It does not select a frontend framework, install application dependencies, overwrite rules, or approve requirements.

Verify `created`, `updated`, `removed`, `unchanged`, conflicts and the final `agents` status; re-run initialization to check idempotence. Report the target project path. Continue requirements-workflow when requirements work was requested. Reviewer TOML templates are installed into the target project’s .codex/agents directory; the plugin templates folder is not itself an autoloaded agent registry.
