# Frontend conventions

Inspect the existing package manifest, framework, components and build scripts before changing code. Preserve established architecture and naming. Select a framework only when the project requires that decision.
Before implementing, read applicable `AGENTS.md` files, configured or discovered project architecture/design documents, and relevant project `standards/` documents. Follow project rules over these general conventions; report conflicts instead of silently choosing. Match the approved `technical-design.md` Architecture and File Change Plan to the current tree. Do not create duplicate context files to satisfy this guidance.
Implement the approved requirements, including applicable loading, empty, error, responsive and accessibility states. Keep business state and API boundaries explicit. Do not embed secrets or fabricate backend behavior.
Use the reviewed task list in dependency order. Requirement or design changes return through requirements-workflow; do not silently edit approved documents.
